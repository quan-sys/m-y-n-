## 3. SETTLED — the rule that replaces the constant

The literal must not be replaced by another literal, by a config key, or by a value derived from a committed output file. It is replaced by two consistency checks that carry no population number at all.

### 3.1 Input check — one shared loader

`scripts/audit_sprint6_readiness.py` gains one function, and it becomes the single place where `step1_survivors.csv` is validated:

```python
def load_survivors_checked(path: Path = SURVIVORS_PATH) -> pd.DataFrame:
    """Read step1_survivors.csv without asserting any expected population size.

    The population is whatever Step 1 produced for the current rebalance.
    Only internal consistency is checked, so a rebalance that legitimately
    changes the survivor count cannot break a downstream script, and a
    corrupted survivor file cannot silently pass one.
    """
```

Its checks, and only these:

1. the `ticker` column exists — otherwise `ValueError`;
2. the frame is non-empty — otherwise `ValueError`;
3. after `.astype(str).str.strip().str.upper()`, no ticker is the empty string — otherwise `ValueError` naming the offending row index;
4. no ticker is duplicated — otherwise `ValueError` listing the duplicated tickers.

It returns the frame with `ticker` already stripped and upper-cased, so callers stop repeating that normalisation.

There is **no** minimum, maximum, or expected count anywhere in it.

### 3.2 Output check — ticker-set equality, not row count

Every place that today asserts `len(output) == EXPECTED_SURVIVORS` is replaced by an assertion that the output ticker **set** equals the survivor ticker set:

```python
def assert_matches_survivors(frame: pd.DataFrame, survivors: pd.DataFrame, label: str) -> None:
    ...
    # raises AssertionError naming `label`, the missing tickers and the extra tickers
```

This is deliberately **stronger** than the check it replaces, not merely different. `len(output) == 156` passes even if a wrong ticker has been swapped in for a right one; set equality does not. Duplicated tickers in the output are also rejected.

### 3.3 Cross-file check — `sprint6_fscore.csv` must match, not merely contain

`scripts/build_sprint6_franchise.py:379` today checks that the F-Score input has 156 rows. It becomes set equality against the survivors, using the same helper.

**The owner must read this consequence before approving.** With today's committed files — survivors 153, `sprint6_fscore.csv` 156 — the Franchise build will refuse to start, reporting the three extra tickers API, DGC and IDJ. That is the intended behaviour: `sprint6_fscore.csv` is a snapshot taken before the warning gate existed, and Franchise must not quietly join a 153-row survivor list onto a 156-row stale score file. The correct sequence after 8E lands is: regenerate `sprint6_fscore.csv`, then Franchise runs. Section 9 assigns that run to the owner.

The alternative — accepting the F-Score file as a superset — is rejected here. It would let a stale score file survive indefinitely, which is the failure this whole block exists to remove.

### 3.4 The generated report sentence

`scripts/analyze_sprint6_annual_history.py:237` writes the literal sentence `... (exactly 156 rows).` into a generated report. The `156` becomes the measured row count of the frame being written. A generated document that states a number must state the number it actually produced.

## 6. The line-number side effect — must be handled, not ignored

`scripts/build_sprint9_4b_annual_pit.py` writes two provenance strings that embed hard-coded line ranges:

That requirement contradicted section 3, which asks for two separate module-level functions and therefore two imported names where one stood before. Section 3 wins. The ranges are expected to move and are repaired by measurement.

The change set must therefore:

**Measure the ranges after the edit and report them.** The implementation must paste back, verbatim, the output of `sed -n '153p;446p' scripts/build_sprint6_fscore.py` and `sed -n '118p;248p;398p;411p' scripts/build_sprint6_franchise.py` taken *after* its edit, alongside the same line numbers read from `git show 30c4aa9:<path>`, so the owner can see with his own eyes which anchors moved and by how much. Guessing, estimating or rounding a new range is a STOP condition. The numbers must come from the file as it lands. `scripts/build_sprint9_4b_annual_pit.py` is therefore an expected member of the change set, not scope creep.

This repair is a patch on a fragile design, not a fix for it: any future edit above those anchors will rot them again.
